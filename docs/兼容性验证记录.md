# 兼容性验证记录

这个页面把三类证据分开记录：

- **自动结构检查**：GitHub Actions 检查 `.dotx` / OOXML 结构、编号、字体、快捷键映射、中文路径和宏文件缺失。
- **完整真机验证**：真实 Windows / Mac 电脑上的 Microsoft Word 桌面版，按 3～5 分钟清单检查关键项目。
- **轻量正常反馈**：用户已经实际用过模板，没有发现明显问题，但没有完成整套验收。

这样不会把“能打开”“用着没问题”和“完整验收通过”混成同一件事。

## 公开记录怎么维护

新版 Issue 表单使用固定标题前缀：

- `[Word 验证]`：完整真机验证；
- `[Word 正常]`：轻量正常反馈；
- `[Word 兼容性]`：v2.4 及更早的旧版反馈入口。

维护者可以直接从 Issues 中搜索这些标题前缀，并把有效结果整理进上面的版本矩阵。这个项目由 ChatGPT 协助维护时，也可以直接让 ChatGPT 读取新反馈并更新矩阵，因此最终用户不需要承担任何整理工作。

## 判定原则

完整验证中的四个关键项目全部正常，才能记录为“关键项正常”；只要有一个关键项目报告异常，就记录为“有问题”，并保留对应 Issue 链接。快捷键单独异常不会自动判定整个模板不兼容，因为快捷键可能受系统、输入法、插件或个人设置影响。

轻量正常反馈只是有价值的使用信号，不等同于完整验证，也不等同于 Microsoft 官方认证。
