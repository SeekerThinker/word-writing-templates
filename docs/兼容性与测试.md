# 兼容性与测试

本项目优先面向 **Microsoft Word for Windows** 与 **Microsoft Word for macOS / MacBook**。普通用户只需要下载与自己系统对应的模板包，解压后双击 `.dotx` 文件即可开始写作。

从 v4.0 起，公开文件名、模板路径和稳定整包下载地址由 [`../STABILITY.md`](../STABILITY.md) 的 4.x 兼容承诺保护。

## v4 的用户矩阵

用户真正需要面对的是 **6 种编号 × 2 个平台 = 12 个统一模板**。每个平台的 Release ZIP 只有 6 个 `.dotx`：3 个书籍模板、3 个文章模板。

仓库在 v4 初期仍会让旧生成器产出 v3 的双版本副本，作为内部兼容构建产物；随后构建步骤把完整结构版本提升到稳定的短文件名。那些历史副本不进入 Release ZIP，也不属于 v4 的用户产品矩阵。

## 自动检查分几层

### 1. 基础模板结构

每次模板相关逻辑发生变化时，GitHub Actions 会在 **Windows、macOS 和 Linux** 三种运行环境中从源码重新生成模板并确认：

- 公共 12 个 `.dotx` 路径存在且可读取；
- 文件是有效的 Word OOXML 模板，不是普通 `.docx` 或宏模板；
- 四级标题编号结构完整；
- Windows / macOS 模板包含各自预期的中文字体；
- 快捷键映射存在；
- 中文文件名和目录能读取；
- 不包含 `vbaProject.bin` 等 VBA 宏内容。

### 2. 思考结构与导航窗格

v4 专项检查会确认：

- 12 个公共模板都包含“标题 2 + 导航窗格”的轻量思考提示；
- 书籍模板已经包含作者、前言、目录、附录、参考文献等可选结构；
- 文章模板已经包含作者、单位、摘要、关键词、参考文献等可选结构；
- `结构标题` 使用非大纲级别，不会挤进 Word 导航窗格；
- 导航窗格仍主要由 `标题 1 / 2 / 3 / 4` 构成，也就是写作者的思考树。

### 3. 成稿 / 打印结构

专项检查覆盖书籍模板的分节、罗马 / 阿拉伯页码切换与重启、镜像页边距、装订线、奇偶页模式、章节自动换页、章节 / 书名 `STYLEREF` 页眉与 `PAGE` 页码字段，以及文章模板的作者信息与页码结构。

### 4. 图表、注释与参考文献

引用专项检查覆盖：

- 中文“图 / 表”题注定义；
- 书籍按一级章编号、文章全文连续编号；
- `Caption` 与“图表来源”样式；
- `Footnote Text / Footnote Reference`；
- `Endnote Text / Endnote Reference`；
- `Bibliography` 与“参考文献条目”悬挂缩进；
- 文档没有启用阻止正常编辑的保护。

### 5. v4 稳定接口

稳定性检查会确认 12 个公共模板路径仍然完整、README 仍使用两个稳定 `releases/latest` 下载地址，并且项目仍明确采用“一套模板，两种使用深度”的 v4 原则。

### 6. 布局与发布包

Ubuntu 主构建会用 LibreOffice 把 **12 个用户模板转换为 PDF** 做布局冒烟测试；README 的 6 张编号预览图也来自实际模板渲染。

用户 ZIP 打包完成后，`release_audit.py` 还会确认：

- Windows / macOS 各有一个版本化 ZIP；
- 每个平台恰好包含 6 个统一 `.dotx`；
- `00-先看这里.txt` 与 `00-开始使用.pdf` 存在；
- 没有 `.dotm` / `.docm`、安装程序或 VBA 宏载荷；
- ZIP 内的 `.dotx` 至少包含 Word 文档、样式和内容类型等必要 OOXML 部件。

通过这些步骤后才发布 GitHub Release。

## 自动检查不能证明什么

自动化检查**不会启动真正的 Microsoft Word**。因此它不能替代真实 Word 环境中的最终体验测试。

例如，系统快捷键、输入法、Word 插件、企业策略、Zotero / EndNote 版本、字段首次刷新行为和打印机驱动，都可能影响实际体验。

所以项目明确区分：

1. **OOXML / 包结构验证**；
2. **LibreOffice 布局冒烟测试**；
3. **真实 Microsoft Word 真机验证**。

前两项通过，不会被写成第三项通过。

## 真实 Microsoft Word 验证

真实使用反馈分为两档：

- **几十秒轻量反馈**：用户已经在 Microsoft Word 桌面版中实际使用过模板，目前没有发现明显问题；
- **3～5 分钟完整验证**：用户逐项检查打开模板、多级标题、正文输入、保存重开，并可额外测试目录、成稿版式、题注 / 引用、脚注 / 参考文献、导航窗格与快捷键。

入口：

- [提交轻量正常反馈](https://github.com/SeekerThinker/word-writing-templates/issues/new?template=word_quick_success.yml)
- [提交完整真机验证](https://github.com/SeekerThinker/word-writing-templates/issues/new?template=word_compatibility_report.yml)
- [`真实Word验收.md`](真实Word验收.md)：普通用户测试步骤
- [`兼容性验证记录.md`](兼容性验证记录.md)：公开验证矩阵

轻量反馈不会被写成完整验证；在没有公开、可追踪的真实记录之前，也不会声称某个具体 Word 版本已经“真机验证通过”。

## Windows 与 macOS 为什么分开下载

两套模板共享相同的结构和编号逻辑，但分别针对常见字体和快捷键习惯优化：

- Windows：宋体、黑体、楷体、微软雅黑等；
- macOS：Songti SC、PingFang SC、Kaiti SC 等。

这样能减少跨平台字体替换造成的版式变化，同时让普通用户不用手工配置。

## WPS 和其他 Office 软件

项目主要保证 Microsoft Word 的使用体验。WPS、LibreOffice 等软件可能可以打开模板，但对 `.dotx`、自定义快捷键、多级列表、字段、奇偶页页眉、镜像页边距和字体替换的实现不同，因此暂不承诺与 Word 完全一致。
