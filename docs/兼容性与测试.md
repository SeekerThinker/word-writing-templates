# 兼容性与测试

本项目优先面向 **Microsoft Word for Windows** 与 **Microsoft Word for macOS / MacBook**。普通用户只需要下载与自己系统对应的模板包，解压后双击 `.dotx` 文件即可开始写作。

## 我们自动检查什么

每次模板发生变化时，GitHub Actions 会在 **Windows、macOS 和 Linux** 三种运行环境中检查同一批成品模板，确认：

- 12 个 `.dotx` 模板都能作为有效的 OOXML 压缩包读取；
- 文件确实是 Word 模板格式，而不是普通 `.docx`；
- 四级标题编号结构完整；
- Windows 与 macOS 模板分别包含预期的中文字体设置；
- 预置快捷键映射存在且结构完整；
- 中文文件名和目录可以在不同操作系统上正常读取；
- 模板不包含 `vbaProject.bin` 等 VBA 宏内容。

Ubuntu 构建流程还会用 LibreOffice 渲染模板预览图，用于尽早发现明显的排版或编号问题。

## 自动检查不能证明什么

自动化检查**不会启动真正的 Microsoft Word**，因此不能代替真实 Word 环境中的最终体验测试。例如：某个系统级快捷键、输入法、Word 插件或企业策略仍可能覆盖模板快捷键。

因此项目采用三层保障：

1. 模板本身的编号、样式和结构不依赖快捷键；
2. 如果某个快捷键不可用，用户仍可直接从 Word 的“样式”区域选择标题和正文样式；
3. 通过公开的真实 Word 验收清单和兼容性反馈，逐步积累可追踪的 Windows / Mac 真机结果。

## 真实 Microsoft Word 验证

真实使用反馈分为两档，证据强度不同，项目会分开记录：

- **几十秒轻量反馈**：用户已经在 Microsoft Word 桌面版中实际使用过模板，目前没有发现明显问题；
- **3～5 分钟完整验证**：用户逐项检查打开模板、多级标题、正文输入、保存重开等关键功能，并可以如实报告异常。

对应入口：

- [提交轻量正常反馈](https://github.com/SeekerThinker/word-writing-templates/issues/new?template=word_quick_success.yml)
- [提交完整真机验证](https://github.com/SeekerThinker/word-writing-templates/issues/new?template=word_compatibility_report.yml)
- [`真实Word验收.md`](真实Word验收.md)：普通用户的测试步骤；
- [`兼容性验证记录.md`](兼容性验证记录.md)：按平台、Word 版本和模板维护公开记录。

轻量反馈不会被写成完整验证；自动结构检查也不会被写成 Microsoft Word 真机测试。在出现公开、可追踪的真实记录之前，项目不会声称某个具体 Word 版本已经“真机验证通过”。

## Windows 与 macOS 为什么分开下载

两套模板共享相同的结构和编号逻辑，但分别针对常见字体和快捷键习惯做了优化：

- Windows：优先使用宋体、黑体、楷体、微软雅黑等常见字体；
- macOS：优先使用 Songti SC、PingFang SC、Kaiti SC 等系统常见字体。

这样可以减少跨平台字体替换造成的版式变化，同时让用户不需要手动配置。

## WPS 和其他 Office 软件

本项目主要保证 Microsoft Word 的使用体验。WPS、LibreOffice 等软件可能可以打开这些模板，但对 `.dotx`、自定义快捷键、多级列表和字体替换的实现不同，因此暂不承诺与 Word 完全一致。
