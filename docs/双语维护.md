# 双语维护约定

[English](bilingual-maintenance.md) · [项目入口](../README.md)

## 范围与基准

项目的**公共用户体验**保持中文、英文语义对应：主页 `site/index.html` ↔ `site/en/index.html`，在线编辑器 `site/editor.html` ↔ `site/en/editor.html`，Word 使用说明 `site/guide.html` ↔ `site/en/guide.html`，编辑器专用说明 `docs/在线编辑器.md` ↔ `docs/online-editor.md`，项目入口 `README.md` ↔ `README.en.md`。

中文产品目的和用户已确认的概念决定是**语义基准**；英文不必逐句直译，但功能、操作顺序、限制、风险提示与链接的含义不能有增减。翻译如果发现概念有问题，先校正中文与决定记录，再同步英文。用户可以独立选择界面语言、文档语言和编号方案；“Chinese traditional chapter numbering”指中文章节**编号**，不能简写成容易误指繁体中文的“Traditional Chinese”。

## 同一个 PR 内同步

修改公共功能、步骤、快捷键、隐私与本地保存声明、兼容性限制、导出格式、表格与脚注时，同一个 PR 检查中英文页面和关联说明。不得只翻译页面标题，却遗漏选择器动态提示或 JavaScript 生成的内容。`site/editor.js`、`site/editor-copy.js`、`site/i18n.js` 和两种语言的 `app.js` 都可能包含用户可见文字。

提交前检查：两种语言的入口和链接都能抵达对应页面；语言切换保留对应上下文；浏览器首次自动选语言但尊重手动选择；两边均明确 JSON 是网页备份、`.docx` 用于 Word 继续；页面预览不承诺精确分页。自动化可检查核心概念与关键标识，但**关键词出现不等于翻译语义已经一致**，仍需人工阅读。

## 不应制造的维护负担

本规则**不宣称仓库中所有历史中文技术文档已经有英文镜像**。Python/JS 源码、OOXML、模板二进制、JSON 结构和测试脚本可以单份维护；过时的中文内部维护资料可逐步整合，在为外部贡献者提供必需操作时优先补英文说明。不要为达到形式上的文件配对而复制几十份容易漂移的状态文件。

面向用户的静态页面可保持各自可索引的语言版本；共用逻辑、模板和测试应尽可能保持一份。中文与英文都是给真实用户阅读的文字，避免生硬机械翻译，也不要为追求优美省略必要的安全说明。
